# Чек-лист выполнения требований на оценку «отлично»

## 1. Основные требования

### Бизнес-логика и роли пользователей

В проекте UrbanWear реализованы роли:

- гость;
- покупатель;
- администратор.

Гость может просматривать каталог, карточки товаров, отзывы и пользоваться корзиной.

Покупатель может регистрироваться, авторизоваться, добавлять товары в корзину, оформлять заказы, добавлять товары в избранное и оставлять отзывы.

Администратор может управлять товарами, категориями, брендами, размерами, отзывами, заказами и пользователями через административную панель Django.

### Валидация бизнес-логики

Реализованы проверки:

- цена товара должна быть больше 0;
- скидка должна быть от 0 до 100 процентов;
- остаток товара не может быть отрицательным;
- количество товара в корзине должно быть положительным;
- нельзя добавить в корзину больше товара, чем есть на складе;
- оценка отзыва должна быть от 1 до 5;
- один пользователь не может оставить несколько отзывов на один товар;
- адрес доставки должен быть корректным;
- сумма заказа должна быть положительной и не превышать установленный лимит.

### Оптимизация запросов

В API используются:

- select_related для категорий, брендов и пользователей;
- prefetch_related для изображений, вариантов товаров, отзывов и избранного.

### Сериализаторы

В проекте используются сериализаторы Django REST Framework.

Реализованы:

- SerializerMethodField;
- передача данных через context;
- вложенные сериализаторы;
- сериализация аннотированных полей.

### SerializerMethodField и context

В сериализаторах товаров реализовано поле is_favorite.

Список id товаров из избранного передается в сериализатор через context из ProductViewSet.

Это позволяет API возвращать флаг, находится ли товар в избранном у текущего пользователя.

### Аннотации

В ProductViewSet используются аннотации:

- avg_rating — средний рейтинг товара;
- sold_count — количество проданных единиц;
- wishlist_count — количество добавлений товара в избранное.

Эти поля выводятся в API и могут использоваться для сортировки.

### Django Filter

Фильтрация товаров реализована через ProductFilter.

Поддерживаются фильтры:

- q — поиск;
- category — категория;
- brand — бренд;
- size — размер;
- min_price — минимальная цена;
- max_price — максимальная цена;
- discount — товары со скидкой;
- in_stock — товары в наличии.

### Postman

Для проверки API подготовлена Postman-коллекция:

postman/UrbanWear_API.postman_collection.json

Коллекция содержит запросы для товаров, категорий, брендов, размеров, отзывов, заказов, избранного и корзины.

## 2. Требования на оценку «хорошо»

### Sentry

В settings.py добавлена интеграция Sentry через sentry_sdk.

Sentry включается через переменную окружения SENTRY_DSN.

### Тестирование

В проекте реализовано 13 тестов.

Проверяются:

- расчёт скидочной цены;
- список товаров API;
- фильтрация товаров;
- аннотации;
- избранное через context;
- добавление товара в корзину;
- запрет добавления количества сверх остатка;
- валидация рейтинга отзыва;
- запрет повторного отзыва;
- валидация товара;
- валидация заказа.

Команда проверки:

python manage.py test

Ожидаемый результат:

Ran 13 tests
OK

### Докстринги и типизация

В доработанных API-классах, сериализаторах, фильтрах, Celery-задачах и служебных методах добавлены докстринги.

В ряде методов используются аннотации типов.

### Django Silk

Django Silk подключен для профилирования запросов.

Маршрут:

/silk/

## 3. Требования на оценку «отлично»

### Celery

Добавлена Celery-задача:

shop.tasks.send_weekly_stock_report

Она формирует отчет по товарам с низким остатком и отправляет письмо администратору.

### MailHog

MailHog используется для локальной проверки отправки писем.

SMTP:

localhost:1025

Веб-интерфейс:

http://127.0.0.1:8025/

### Деплой

Проект подготовлен к деплою.

Добавлены:

- .env.example;
- Dockerfile;
- Procfile;
- README_DEPLOY.md;
- docker-compose.yml.

### OAuth2

OAuth2 реализован через django-allauth и Google Provider.

Маршруты авторизации:

/accounts/login/

Для полноценной работы необходимо создать Google OAuth Client ID и Client Secret и добавить Social Application в Django Admin.
